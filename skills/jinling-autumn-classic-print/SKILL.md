# 金陵秋日 · 古典版画

这是一套**设计流程与视觉风格技能**，不是八张图片的固定模板或批量导出器。先保真，再以冷纸白、雾蓝、靛青和克制秋色重绘。资产与脚本只是示范和辅助，不强迫新项目沿用本系列标题、地点数量、布局或尺寸。

## 按任务读取

- 新绘或改绘：读 [视觉规范](references/style.md) 和 [地点锚点](references/locations.md)，按需要查看 references/presets 内对应地点。
- 梳理创作思路与撰写提示词：使用 [设计简报与绘图提示结构](references/design-brief.md)，先决定画面要表达什么，再决定怎样绘制和摆放。
- 组成封面或提案卡：读 [工作流](references/workflow.md)。现成源稿在 assets/designs，每张图有独立素材；成品参考在 assets/final-designs。
- 修改现有示例或导出：读 [重建说明](references/rebuild.md)；文字与布局以 layout.svg 为准，design.json 是文案和素材清单，修改时同步。
- 交付或公开分享：读 [验收清单](references/checklist.md) 和 [来源说明](references/provenance.md)。

## 制作约束

1. 开始真实地点绘图前实际查看实拍，列出可见建筑、植物、岸线或道路锚点。搜索摘要不等于视觉核验；低清照片不足以验证的细部不得声称准确复原。无法看图时请求参考，不凭空补建筑。
2. 插画用可用的图像生成/编辑工具独立绘制；没有工具就说明限制，不用代码假画替代。不要默认调用付费 API 或索取密钥。
3. 提案卡允许“完整无字主图 PNG + 四张细节 PNG”，不强制把每片叶子拆层。但不能把完整含字海报作为交付替代。标题、说明、线条、色板由本地字体及矢量对象排版；只有用户明确要求的场景内牌匾可随插画生成，并检查字形。
4. 四格细节分别关注形态、材料、建筑构件或空间关系；不能以相似裁切凑数。纸纹仅为背景，不能占据细节名额。需要完整形体时给主体四周留余量。
5. 不把亮黄树叶、HDR 或密集噪点当作秋色和纸质。使用低饱和暖色点染、冷灰深色和可独立调节的纸纤维层。
6. 先确定插图在版面中的目标比例，再绘图。区分“画面内部留白”与“标题旁的版面空隙”；后者可能需要扩展图框，而不是向原窄图框硬塞素材。比较素材/图框比例，禁止非等比拉伸，检查裁切后的主体位置与完整性。
7. 改稿遵守最小改动：用户已认可的主图不自行重绘，未要求改的文字、背景与配图保持不变。明确确认有歧义的标题，不自行润色。
8. 默认一份自包含 SVG 与一张按目标尺寸直接渲染的全彩无损 PNG；尺寸服从当前用户要求，不擅自添加多版本。附带位图的 SVG 不宣称纯矢量，输出画布分辨率不等于素材原生细节。

## 当前示例的约定

- 封面两行：秋天的金陵城 / 可能会是什么样子的；玄武湖宽幅图向左扩展，紫峰位于插图中央，低饱和秋叶。下方直接使用主题名称，不另加单字标签。
- 七页栏目名为“此间秋意”；随园为“百年银杏”；正式图不出现样张或待核验字样。
- 栖霞山是实拍门头加红枫；石象细节呈完整轮廓；颐和路为黄墙；燕雀湖与已确认构图保持一致。
- 示例为 6144×4096、3:2。每图资产集中在自身文件夹，弃用候选不混入正式素材。

交付前逐张看最终渲染，并运行校验。脚本通过不能代替地点真实性、中文字形、拼接观感与审美检查。保存简明日志：采用素材、改变范围、实际检查和未解决事项。不要自动上传、公开用户照片或替项目指定许可证。
